# UBS約1年比較における疎な生成ティック補完の扱い

日付: 2026-09-02

## 変更前

実ティック監査は、`real ticks absent`または`every tick generation used`が1件でもあれば、期間の同期範囲にかかわらずFAILとしていた。この厳格な既定動作は、短期スモークで履歴不足を検知するために維持する。

## 変更理由

約1年比較の実ティック1件目では、同期範囲が`2025.01.02`～`2026.08.28`で対象期間全体を覆い、テストも正常完了した。一方、対象352,554分足のうち24分だけ実ティックがなく、補完率は約0.0068%だった。この疎な配信欠損を、期間端の履歴不足や日単位の全面欠損と同じFAILとして扱うと、長期モデル比較を不必要に中断する。

## 変更後

- 監査関数の既定値は従来どおり補完率0%を要求し、既存スモークの判定を変更しない。
- 約1年のモデリング方式比較だけ、同期範囲が対象期間全体を覆い、テストが完了し、集計警告から補完率を算出でき、補完率が0.01%以下の場合は注記付きPASSとする。
- 補完分数、総分足数、補完率、許容閾値、警告本文は成果物へ残す。
- 期間端不足、テスト未完了、集計値を解析できない警告、0.01%超過は引き続きFAILとし、後続ケースを開始しない。

この変更は成績の採否基準ではなく、実ティック入力データ品質ゲートの長期比較向け許容差である。
