# QQ WF2～WF4 Capital Stress追加

日付: 2026-08-20

## 変更前

- シナリオ検証、set検証、レポート名、マニフェストのWF表記がWF1専用である。
- BenchmarkはPF、RF、Sharpe、Equity DDをすべて必須としている。
- WF1は手動HTML相当の指標基準が揃っているが、WF2～WF4には手動Testerログだけがあり、PF、RF、Sharpe、Equity DDの手動基準値は残っていない。

## 確認できた正本

- WF2: 2025-10-01～2025-12-31、NFP Filter=true、Friday Night=true
- WF3: 2026-01-01～2026-03-31、NFP Filter=false、Friday Night=true
- WF4: 2026-04-01～2026-06-30、NFP Filter=false、Friday Night=false
- 全WF共通: Fixed Lot 0.01、OrdersMax 10、DD Mode 0、DD Value 0、S07のみ有効
- その他の入力は各期間のMT5 Testerプロファイルを正本とする。

## 変更理由

利用者の指示により、QQのWF2、WF3、WF4について1000 USDと3000 USDのCapital Stress Testを追加する。WFごとのWFO選択値を混同せず、手動ログで確認可能な範囲をSafety Gateにする必要がある。

## 変更方針

- `wf`、期間、専用set、出力先、BenchmarkをシナリオJSONで指定する。
- WFごとに専用setを新規作成し、汎用setと既存WF1 setは変更しない。
- 各WFは3000 USDを最初に実行し、Net Profit、Trades、deal数、deal日時・方向・価格を手動ログと照合する。
- Net Profit許容差は既承認基準の±0.5%または±0.10 USDを使用する。
- 手動基準が存在しないPF、RF、Sharpe、Equity DDはゲート対象外とし、自動結果として記録する。
- 3000 USDがPASSしたWFだけ1000 USDへ進む。
- レポート名、ログ、マニフェストはWF名を設定から生成し、PythonへWF2～WF4専用分岐を作らない。
- 3つのWFキャンペーンは直列実行し、結果を別々のdataフォルダへ保存する。

## 影響

WF1の設定と既存結果は維持する。EA、モデル、No Delay、レバレッジ、通貨、LotなどCapital以外の条件は変更しない。Git設定は行わない。
